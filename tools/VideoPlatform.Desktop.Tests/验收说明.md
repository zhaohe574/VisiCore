# 桌面端与更新器验收

## 自动测试

客户端测试使用真实视图模型和独立测试替身，覆盖认证并发、撤权、全局通道隔离、媒体资源释放、回放控制、轮巡、报警处理和安装包完整性。模拟通道不会计入真实设备验收。

```powershell
& "$env:LOCALAPPDATA/VideoPlatform/dotnet/dotnet.exe" test tools/VideoPlatform.Desktop.Tests/VideoPlatform.Desktop.Tests.csproj -c Release --filter 'Category!=Package'
& "$env:LOCALAPPDATA/VideoPlatform/dotnet/dotnet.exe" test tools/VideoPlatform.Desktop.Tests/VideoPlatform.Desktop.Tests.csproj -c Release --filter 'FullyQualifiedName~VisualSmokeTests'
```

第二条命令在 STA 线程创建 WPF 应用资源，使用 `RenderTargetBitmap` 生成 24 张 PNG。输出位于本目录 `screenshots`，包含实时、回放、报警和导出四个视图，以及 1366×768／1920×1080 和 100%／150%／200% 共六组组合。渲染图物理像素与标称分辨率一致，使用对应 DPI 绘制文字；低分辨率高缩放下提供工作区滚动，不隐藏操作。测试还捕获 WPF 数据绑定错误并验证像素非空。

渲染测试没有改变 Windows 系统缩放，不能替代真实屏幕 DPI 切换、原生视频窗口或硬件解码验收。

界面测试共用集合级 STA 宿主，并在集合结束时关闭应用、等待线程退出。测试通过仅内部可用的 `App(startDesktop: false)` 加载正式 XAML 资源并处理启动事件，跳过正式服务、主窗口和 MessageBox 异常处理的初始化；正式无参构造保持默认启动。WPF 在构造应用时排入启动回调，即使没有调用 `Run`，渲染过程处理 Dispatcher 队列也会触发该回调；单纯延长超时无法修复这种阻塞。视觉测试限时 30 秒，已取消五分钟等待。`AppStartupIsolationTests` 验证启动回调已执行、资源可用、没有主窗口，以及同步和异步异常能回传测试并继续复用宿主。

## 安装与回滚

```powershell
& tools/v2-package.ps1 -VerifyInstallation
```

脚本生成自包含 x64 发布目录、正式未签名 MSI、便携 ZIP、哈希清单，以及独立的 2.0.0 基线／2.0.1 正常升级／2.0.2 故障注入安装包。验收安装包使用随机 UpgradeCode、独立注册表路径、独立快捷方式和当前用户安装范围；正式包使用原平台 UpgradeCode 与按计算机安装范围。

测试顺序为安装基线、错误哈希拒绝、受控安装失败并核对旧版本文件与注册表、验证旧进程重启探针、正常升级并核对新版本、卸载验收产品。故障注入只在验收 MSI 的条件编译分支中存在，正式包不包含故障动作。所有安装等待正常返回，不强制关闭用户程序。

`artifacts/v2-desktop/qa-*` 保留安装／卸载 MSI 日志、TRX 测试结果和中文验收记录。更新器安装阶段日志在当前用户 `LocalAppData/VideoPlatform/msi-*.log`，安装包缓存位于同目录的 `packages` 子目录。

## 实机检查矩阵

| 物理分辨率 | 系统缩放 | 操作检查 |
| --- | --- | --- |
| 1366×768 | 100% | 登录、资源树、16 分屏、回放栏、报警详情、导出任务 |
| 1366×768 | 150% | 同上，并检查工作区滚动和工具提示 |
| 1366×768 | 200% | 同上，并检查滚动后的按钮与窗口命中区域 |
| 1920×1080 | 100% | 同上，并检查全屏与单窗口放大 |
| 1920×1080 | 150% | 同上，并检查原生视频控件的窗口位置 |
| 1920×1080 | 200% | 同上，并检查最大化、还原和跨屏移动 |

1. 使用具有受信任 HTTPS 证书的平台地址登录。证书无效时请求应失败，不接受跳过 TLS 校验作为通过。
2. 打开真实 H.264 和 H.265 通道，检查原生视频画面、运动、声音、截图尺寸与图像内容。切换报警／设置、放大、全屏和还原后，原生视频窗口不能覆盖其他页面。
3. 连续切换 1／4／9／16 分屏并拖放通道。停止窗口后核对服务端会话释放，缩减分屏后隐藏窗口不得继续占用媒体配额。
4. 检索具有缺口的真实录像，核对时间轴段落、独立与统一暂停／恢复／定位／倍速。定位后画面应进入目标时间，不能持续显示旧缓冲。
5. 拔断网络再恢复，核对重连和租约回收。持续运行 24 小时，记录进程内存、句柄、CPU、解码窗口和服务端会话数量。
6. 两个账号争用同一云台，后者收到占用提示。松开鼠标、失焦、切换通道和退出均停止；断网后由服务端 10 秒租约停止。
7. 通过另一管理会话撤销数据范围或媒体权限。原窗口、回放、下载及云台立即停止；无权通道从资源列表消失，后续轮巡不得重新打开。
8. 报警认领、备注、关闭与重开后在另一端查看历史；设备恢复事件不能自动关闭人工处理状态。
9. 提交真实导出任务并取消／重试，校验下载文件与录像时间清单。取消下载不得留下目标文件的半成品。
10. 在获准的管理员测试机安装正式 MSI，验证 UAC、开始菜单、桌面快捷方式和正式 1.x 升级目录继承。此项与当前用户范围的隔离安装测试分别记录。

## 需要单独记录的限制

- 稀疏窗口布局使用可空通道数组保留窗口位置，生成客户端已接入认证和业务调用；生成客户端接入后的自动回归为 71 项通过。
- 两路真实主码流通过 WPF 原生截图及播放器释放检查，证据位于 `candidate-evidence`。该检查不替代全部物理屏幕与 DPI 组合、原生窗口遮挡或长时间运行验收。
- 最终 MSI、ZIP 内的程序集与发布目录一致，安装升级、故障回滚及产物回归共 5 项通过，详见 `安装包产物一致性.md`。
- 没有代码签名证书，发布产物为未签名。正式 MSI 的管理员安装与 24 小时值守不得使用隔离安装或模拟测试结果替代。
