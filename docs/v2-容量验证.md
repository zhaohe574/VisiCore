# 第二版 API 容量验证

## 验证边界

本工具验证真实 .NET 10 API、认证、数据库访问、媒体会话控制、播放鉴权和资源释放。适配器及 ZLMediaKit 控制接口为独立 HTTP 模拟服务，没有视频字节传输、SDK 调用、FFmpeg 转码或播放器解码。

工具不连接已运行的 `5082` API，不访问 `10.37.200.74`，不改变业务数据。每轮创建随机命名的 `vp_load_*` 测试数据库，启动独立 API 子进程与随机回环端口的模拟服务；结束时通过真实 API 释放媒体和登录会话，核对两侧资源归零，再终止自己的进程并删除本次测试数据库。

以下模拟结果只能支持相应配置下的控制接口容量结论。真实媒体使用独立工具验收，结果见本文末尾，不能混入模拟工具成绩；24 小时值守仍需独立验收。

| 项目 | 数量或规则 |
| --- | --- |
| 账号 | 恰好 800 个，包含 1 个管理员、799 个普通账号 |
| 权限数据 | 普通账号使用真实角色权限和逐通道显式授权，合计 64719 条用户范围记录 |
| 设备与通道 | 1 台模拟录像机、81 路在线模拟通道 |
| 登录 | 100 个不同账号从同一出口同时调用真实桌面登录接口 |
| 实时 | 100 个客户端各创建 1 个会话，共享同设备、通道、码流和输出配置的 1 个模拟上游 |
| 回放 | 前 20 个客户端分别创建独立回放，模拟上游和流标识均为 20 个 |
| 播放连接 | 调用真实 `/internal/zlm/on-play` 完成 100 个实时、20 个回放鉴权，数据库记录 120 个观看连接 |
| 查询 | 100 个客户端轮询通道、报警、组织、布局及收藏；默认查询后等待 1000 毫秒 |
| 媒体续期 | 建立后、结束前及每 60 秒调用真实续期接口，检查剩余租期大于 2 分钟 |
| 认证续期 | 100 个账号真实调用刷新接口，并断言令牌保持稳定 |
| 释放 | 真实 DELETE 媒体和退出登录；数据库、模拟适配器及观看连接都必须归零 |

账号准备使用正式 PBKDF2 算法；批量账号复用本次随机测试密码的散列，准备过程不计入 HTTP 请求时间，登录仍进行正式算法校验。默认报警、组织、收藏和布局为空，因此这些页面的查询结果不能外推为大量历史业务数据的性能。

普通查询按每个客户端独立计时，启动错开 0～990 毫秒，使用有思考间隔的封闭式负载，不是无限速压力测试。每次请求从发送前开始计时，到响应体完整读取为止；报告包含失败请求、HTTP 状态分布、P50、P95、P99、最大值及所有原始耗时样本。分位数使用最近秩法，登录和建流不混入普通查询 P95。

成功条件：数据和模拟上游数量核对通过，全部 HTTP 请求成功，普通查询总 P95 小于 500 毫秒，结束前仍保持目标会话数，资源释放归零，测试数据库删除成功。失败时返回非零退出码并保留失败报告。

## 配置与运行

需要 .NET 10 SDK，以及允许创建、删除测试数据库的 PostgreSQL 账号。数据库连接必须指向授权测试实例。工具不创建数据库集群、不修改现有 PostgreSQL 配置，也不负责重启既有 API。

| 环境变量 | 作用 | 默认值 |
| --- | --- | --- |
| `LOAD_TEST_DATABASE_URL` | 测试 PostgreSQL 管理连接串 | 必填 |
| `LOAD_TEST_API_DLL` | 本轮测试的真实 API DLL 完整路径 | 必填 |
| `LOAD_TEST_DOTNET` | .NET 10 的 dotnet 可执行文件 | 当前 dotnet 进程路径 |
| `LOAD_TEST_DURATION_SECONDS` | 普通查询时长，5～300 秒 | 30 |
| `LOAD_TEST_THINK_MS` | 每次查询后的等待时间，0～10000 毫秒 | 1000 |
| `LOAD_TEST_API_POOL_SIZE` | 测试 API 数据库池上限，4～200 | 64 |
| `LOAD_TEST_OUTPUT` | 报告输出根目录 | `tools/VideoPlatform.LoadTests/results` |

```powershell
& 'C:/Users/57477/AppData/Local/VideoPlatform/dotnet/dotnet.exe' build 'src/VideoPlatform.Api/VideoPlatform.Api.csproj' -c Release -o 'tools/VideoPlatform.LoadTests/.runtime/api'

$env:LOAD_TEST_DATABASE_URL='Host=127.0.0.1;Port=55485;Database=postgres;Username=postgres'
$env:LOAD_TEST_API_DLL='D:/2026-09-03 afglpt/tools/VideoPlatform.LoadTests/.runtime/api/VideoPlatform.Api.dll'
$env:LOAD_TEST_DOTNET='C:/Users/57477/AppData/Local/VideoPlatform/dotnet/dotnet.exe'
& 'C:/Users/57477/AppData/Local/VideoPlatform/dotnet/dotnet.exe' 'tools/VideoPlatform.LoadTests/bin/Release/net10.0/VideoPlatform.LoadTests.dll'
```

示例端口 55485 是本次验证期间建立的独立本机 PostgreSQL，实际执行前需使用可用的测试实例。第一条命令将当前真实 API 构建为专用快照，不重启或覆盖正在运行的 5082 服务。主代理若修复了 API／基础设施，必须重新执行该构建，不能将旧 DLL 的测试结果归到新版本。

重复运行无需手动清空数据，每轮都有新数据库、随机测试密码、API 端口和结果目录。将时长设为 70 秒可覆盖至少一次第 60 秒的自动媒体续期。工具只使用桌面 Bearer 令牌；Web Cookie／CSRF 流程由功能测试覆盖，本工具不绕过或修改这些规则。

每轮生成 `report.md`、`report.json` 和 `api.log`。JSON 包含测试参数、运行环境、API 和核心依赖 DLL 的 SHA-256、数据库／模拟器加载及清理快照、各阶段指标、逐请求耗时及失败原因，不写登录密码或访问令牌。运行时目录和结果目录已由工具自己的 `.gitignore` 排除。

## 已完成实测

日期：2026-09-07。环境：Windows x64、12 个逻辑处理器、.NET 10.0.11、PostgreSQL 17.6。负载工具、API、模拟器与数据库在同一台机器。API 使用真实 2.0.0 候选构建，登录限流为同出口每分钟 200 次；账号失败锁定规则保持原样。

### 首轮暴露的问题

数据库 `max_connections=100`，API 池上限也是 100 时，100 次登录成功，但并发建流出现 1 次 HTTP 500。API 日志明确返回 PostgreSQL `53300: sorry, too many clients already`。测试准备连接、管理连接和 API 共用数据库实例，池上限不能直接等于整个数据库的最大连接数。

失败报告保留在 `tools/VideoPlatform.LoadTests/results/20260907-022517-d9c02738`。它不计作容量通过。后续测试显式设置 API 池为 64，为其他连接留出空间。生产部署也应统一预算 API、Worker、管理任务的池容量，而不是逐进程各占用整个数据库配额。

## 未覆盖事项

未覆盖真实媒体码率、网络出口带宽、SDK 登录或回放容量、H.265 解码、FFmpeg 转码、磁盘写入、真实 ZLMediaKit 性能、HTTPS／代理开销、大量历史报警查询、数据库主备切换和 24 小时连续运行。

当前成绩不应写成“支持 100 路真实视频”或“实机 20 路回放通过”。它表示在上述同机测试配置与模拟数据规模下，真实 API 能建立和维护目标数量的控制会话，并完成所述普通查询负载。
