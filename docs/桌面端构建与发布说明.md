# 桌面端构建与发布说明

## 构建

在 Windows x64 开发机执行：

```powershell
dotnet build VideoPlatform.sln --configuration Release
dotnet publish src/VideoPlatform.Desktop/VideoPlatform.Desktop.csproj --configuration Release --runtime win-x64 --self-contained true -o artifacts/desktop-win-x64
dotnet publish src/VideoPlatform.Updater/VideoPlatform.Updater.csproj --configuration Release --runtime win-x64 --self-contained true -o artifacts/desktop-win-x64
```

两个项目发布到同一个目录，更新器会随桌面端文件一起进入安装包。当前桌面端与更新器版本为 `1.0.1.0`。MSI 通过 WiX 文件版本绑定读取桌面端 EXE 版本，无须手工同步版本号。API 比较时将 `1.0.1` 与 `1.0.1.0` 视为相同版本。

## MSI

需要 WiX 6：

```powershell
wix build deploy/VideoPlatform.Desktop.wxs -arch x64 -o artifacts/VideoPlatform.Desktop-x64.msi
wix msi validate artifacts/VideoPlatform.Desktop-x64.msi
wix msi decompile artifacts/VideoPlatform.Desktop-x64.msi -o artifacts/msi-inspect.wxs
```

反编译结果应包含 `VideoPlatform.Updater.exe`，文件组件为 `always64`。必须指定 `-arch x64`，否则 WiX 默认生成 x86 安装包。MSI 是自动更新格式，ZIP 和 EXE 只用于手工下载，更新器会拒绝自动安装这两种格式。

## 自动更新流程

桌面端启动和登录后请求 `/api/desktop-releases/latest?currentVersion=版本号`。普通更新显示新版本，通过“检查更新”执行；强制更新暂停工作区并立即执行，已知的强制版本要求保存到本地，断网重启后继续提供重试入口。

单文件更新器复制到临时目录后启动，避免安装时替换正在使用的更新器。参数通过 `ArgumentList` 传递。更新器下载临时文件、校验 SHA-256、保留安装源缓存、等待主程序退出，再调用 `msiexec.exe` 安装并重启桌面端。成功码包括 `0`、`3010` 和 `1641`，后两种记录需要重启系统。

校验后的安装源保存在 `%LOCALAPPDATA%\VideoPlatform\packages`。Windows Installer 修复与失败升级回滚可能再次读取原始安装源，因此不要在安装后立即清除此缓存。MSI 的旧版卸载位于安装事务内，安装失败可以回滚。

网络不可用、哈希错误、安装失败或包格式不符合要求时，旧版本不会被主动删除。普通更新失败尝试重启旧版，强制更新失败显示重试入口。中文更新日志为 `%LOCALAPPDATA%\VideoPlatform\updater.log`，MSI 详细日志为同目录的 `msi-时间.log`。`--verify-only` 只下载和验证，不安装或重启，用于包校验。

## 验收

- 检查正确 SHA-256 能完成安装并重启。
- 检查错误 SHA-256 保留旧版本并写入中文日志。
- 检查非 MSI 地址被拒绝并提示手动处理。
- 检查 `msiexec` 失败退出码保留旧版本，`3010` 和 `1641` 按成功处理。
- 检查普通更新网络失败后仍可继续使用桌面端。
- 当前未接入 Windows 代码签名，签名证书准备后再加入发布流水线。

## 本地回归命令

```powershell
node tools/client-checks.mjs
dotnet run --project tools/VideoPlatform.Checks --configuration Release
tools/wix6/wix.exe build tools/updater-test.wxs -o artifacts/updater-test.msi
tools/wix6/wix.exe build tools/updater-test.wxs -d TestVersion=1.0.1 -d FailUpgrade=1 -o artifacts/updater-fail-test.msi
$env:VIDEO_PLATFORM_TEST_MSI = "$PWD/artifacts/updater-test.msi"
$env:VIDEO_PLATFORM_TEST_FAIL_MSI = "$PWD/artifacts/updater-fail-test.msi"
dotnet run --project tools/VideoPlatform.Checks --configuration Release
```

默认检查覆盖客户端并发续期、WPF 分屏、树搜索、播放器释放、关闭重入、会话引用计数和哈希校验。设置两个测试 MSI 环境变量后，会实际安装仅包含测试标记的独立产品，检查失败升级回滚与重启，并卸载测试产品；不会安装正式桌面端。该检查不等同于真实摄像机多路解码、PTZ 和报警联调。

## 内部 HTTPS 证书

服务器 `https://10.37.200.74` 使用内部自签名证书，Nginx 已绑定证书并将 80 端口跳转至 HTTPS。桌面端和浏览器所在 Windows 必须信任该证书；否则 TLS 校验会拒绝连接，不能通过跳过证书校验处理。

当前用户可运行以下命令导入随项目保存的公钥证书：

```powershell
powershell -ExecutionPolicy Bypass -File tools/install-platform-certificate.ps1
```

证书会导入当前用户的“受信任的根证书颁发机构”，不包含私钥。其他 Windows 用户或电脑需要各自导入；正式对外部署应改用绑定域名的受信任 CA 证书，并在 Nginx 中替换 `ssl_certificate` 和 `ssl_certificate_key` 路径。
