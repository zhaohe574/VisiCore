## 权限与页面复核矩阵

| 业务面 | 路由／接口范围 | 权限边界 | 已覆盖的失败行为 |
| --- | --- | --- | --- |
| 认证与个人资料 | `/auth/*`、`/app/profile` | 当前会话；写入需 HTTPS 和 CSRF | 401 清会话、CSRF 失败单次重取、表单错误保留上下文 |
| 设备与通道 | `/devices`、`/channels`、`/app/devices`、`/app/organization` | `device.*`、`channel.*`、节点和通道范围 | 401／403、设备同步、通道密码不回显、重复提交由按钮加载态阻断 |
| 值守与媒体 | `/live-sessions`、`/playback-sessions`、`/app/live`、`/app/playback` | `live.view`、`playback.view`、通道范围 | 断线重连、会话续期、停止操作幂等、失权后资源回收 |
| 报警与导出 | `/alarms`、`/exports`、对应页面 | `alarm.read`、`alarm.ack`、`export.*` | 状态冲突返回 409；取消／重试和队列租约有恢复测试 |
| 管理与发布 | 用户、角色、会话、审计、版本、SSL、设置 | `user.*`、`role.*`、`session.manage`、`desktop.release.manage`、`ssl.*` 等 | 受限账号显示访问受限；分页、冲突和错误响应统一 |

## 验证结果

- `npm test --prefix web-admin`：65 项通过。
- `npm run build --prefix web-admin`：通过。
- `dotnet build VisiCore.slnx --no-restore`：0 警告、0 错误。
- `dotnet test VisiCore.slnx --no-restore`：170 项通过；34 项因未配置真实数据库或 Windows 实机环境跳过。
- `node tools/VideoPlatform.ClientGenerator/verify.mjs`：16 项通过，生成客户端与服务端规范一致。
- 远端桌面 User-Agent 的 `/`、`/app` 返回 200；Android／iPhone User-Agent 对 `/`、`/app`、`/api` 和 `/health` 返回 403 并显示 PC 提示；桌面 `/health` 返回 200；`visicore-p2p` 未启用、未运行。API、Worker、适配器和 ZLMediaKit 进程均 active，但 Worker 当前因设备 3 的外部网管依赖不可达而为 `degraded`，不能宣称全量健康通过。

## 尚需现场条件的项目

以下项目需要独立测试数据库、真实测试账号、两路真实设备或 Windows x64 实机，不能用本地模拟结果代替：

1. 生产数据库清库／重建前的完整备份校验、隔离库恢复演练和破坏性迁移窗口。
2. Worker、Nginx、服务启动、健康检查和部署中断故障注入，以及对应快照回滚。
3. 100%／125%／150%／200% DPI、多显示器、perMachine UAC 升级回滚和断网安装矩阵。
4. 独立测试账号两路真实设备的 24 小时连续值守。历史值守因认证凭据失效提前停止，不能标记为通过。

未完成项目保留原始失败报告和现场限制，不通过删除证据或伪造签名、实机和恢复结论来闭合。
