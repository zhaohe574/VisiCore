# VisiCore（视枢） 2.0 架构说明

## 部署结构

平台采用 .NET 10 模块化单体。API 负责认证、权限、设备、媒体、报警、导出和版本接口；Worker 负责同步、报警入库、媒体回收、导出队列、保留期清理和资源核对；海康适配器按录像机隔离 SDK 登录、回调、重连、媒体和报警状态。ZLMediaKit 的媒体端口监听全部网卡，使用防火墙限制访问，HTTP 管理接口另外限制来源为回环地址；公开媒体由 Nginx 提供 HTTPS 入口。

PostgreSQL 保存业务数据、会话、媒体租约、导出任务、报警检查点、审计记录和事务发件箱。Npgsql 使用连接池和参数化 SQL。迁移脚本写入 `schema_migrations` 并校验 SHA-256，API、Worker 与适配器通过回环 HTTP 通信，Nginx 提供 HTTPS、同源 Web、SignalR 和鉴权媒体代理。

## 数据与权限

所有媒体操作使用全局 `channelId`。服务端从通道记录解析设备和设备内编号，媒体流名同时包含设备、通道、码流和输出配置。账号、角色和范围必须同时通过功能权限与通道范围检查；普通账号未配置范围时无权访问。会话在服务端可撤销，Web 使用 Secure、HttpOnly Cookie 和 CSRF，桌面令牌使用 DPAPI 保存。

权限撤销会主动回收相关媒体、云台租约和导出任务。SignalR 事件只携带资源 ID、事件版本和事件类型，客户端收到后重新查询；断线恢复通过接口补取最新状态。

## 可靠性

媒体和云台停止使用幂等操作、租约、引用记录和后台重试。Worker 在停止失效资源前重新读取租约到期时间，避免刚续期的资源被旧巡检停止。导出使用 PostgreSQL 咨询锁和 `FOR UPDATE SKIP LOCKED`，取消未获设备确认前保留占位，重试会拒绝重入旧任务。报警按设备分段日志、检查点和幂等源 ID 入库，未知报文保留原始内容。

## 客户端

Web 使用 Vue 3、Vue Router、Pinia、Element Plus 和按页面延迟加载；实时视频使用鉴权 HTTPS FLV 与 mpegts.js。WPF 使用 CommunityToolkit.Mvvm、依赖注入和 LibVLCSharp，优先通过鉴权 HTTPS MPEG-TS 原生解码 H.264／H.265，支持 1／4／9／16 分屏、回放控制、轮巡和云台。Web 使用生成类型，桌面认证与业务服务调用生成的 C# 客户端，并统一映射界面模型和中文错误。生成工具位于 `tools/VideoPlatform.ClientGenerator`。

## 容量边界

默认每用户最多 16 路实时、4 路回放；每设备最多 20 路回放，全局 32 路回放，兼容转码全局 4 路。导出全局 2 个、每设备 1 个。生产数据库连接池为 API 64、后台任务 16，保留管理连接和设备任务余量。模拟容量实测为 800 个账号、100 个登录、100 个共享实时订阅和 20 个独立回放；该结果不代表真实设备媒体容量。
