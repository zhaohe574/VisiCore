## 检查命令

以下命令在工作区执行，Python 需要安装 Paramiko，SSH 凭据从 `VIDEO_PLATFORM_SSH_PASSWORD` 环境变量读取。

```powershell
python tools/v2-remote-checks.py health
python tools/v2-remote-checks.py logs
python tools/v2-remote-checks.py access --transport flv
python tools/v2-remote-checks.py access --transport ts
python tools/v2-native-media-check.py --base-url https://10.37.200.74
python tools/v2-soak.py status
```

`health` 检查服务和业务接口；`logs` 只读取当前系统启动中、各服务当前运行实例且主进程启动时间之后的最近 45 条日志，每服务最多输出 12000 字符。服务未运行时不回退查询旧日志；读取期间发生重启时重试一次，仍不稳定则跳过。日志先脱敏再截断，隐藏已配置密钥及其 URL 编码、JSON 转义形式，以及令牌、密码、Bearer 凭据、Cookie 和 URL 用户信息。脱敏配置不可读时直接失败。

`access` 默认使用 FLV。`--transport ts` 从会话返回的 `httpTsUrl` 提取 `/media/` 后的路径，按现有验证方式连接本机 ZLMediaKit 的 18082 端口，检查两个观看者共享上游、撤权后原连接结束，以及合法观看者继续收流。该检查会创建测试角色和用户、拉流并撤权，结束后禁用测试用户；它不覆盖客户端到 Nginx 的 HTTPS 链路，完整 HTTPS-TS 验证仍需桌面端或浏览器实测。设备同步使用 `device`，实时、回放和导出验证使用 `media`；这些操作均应避开正在进行的实机测试。

## 发布步骤

1. 使用 .NET 10 分别发布 API、Worker、适配器；使用 `npm run build` 生成 Web；使用 `tools/v2-package.ps1` 生成 Windows x64 MSI、便携 ZIP 和哈希清单。
2. 设置 `VIDEO_PLATFORM_SSH_PASSWORD` 后运行 `python tools/v2-deploy.py --release <版本>` 上传候选。候选入口使用 HTTPS 8443，原 443 入口保持不变。服务器需具备 Python 3.9 及以上、Nginx、systemd、PostgreSQL、`liteware` 账户及原版配置、证书和 SDK。
3. 执行健康检查、设备同步、真实实时／回放／导出验证，再检查 OpenAPI、下载文件大小和 SHA-256。
4. 候选验证完成并进入切换窗口后执行下述 `switch` 命令。切换会重启第二版 API、Worker 和适配器，现有观看连接会受影响。

## 正式入口切换

```powershell
python tools/v2-remote-checks.py switch
```

该命令通过 SSH 在服务器内存中运行工作区当前的 `deploy/v2-install.py`，无需重新上传发布产物，也不依赖候选目录中旧安装器是否已有回滚实现。服务器上已经更新安装器时，也可使用 `sudo python3 /opt/video-platform-v2/current/deploy/v2-install.py switch`。

安装器保留原有安装形式：`sudo python3 <新版安装器路径> <候选发布目录> --public-port 8443`。追加 `--switch` 表示安装完成后切换正式入口。第二版已经使用正式 URL 时，后续安装必须显式追加 `--switch`，以免将公开 URL 意外改回 8443。候选端口必须独立，不能以 `--public-port 443` 绕过正式切换流程。

每次安装或切换均执行以下步骤：

1. 获取独占锁，确认无待恢复操作，执行现有配置的 `nginx -t`，验证当前运行服务及现有 HTTPS `/health`。前置验证失败时不修改运行配置。
2. 在 `/var/lib/video-platform-v2-deploy/snapshots/<快照编号>/` 保存本次操作前的配置、`current` 原始链接目标、四个 systemd 单元文件及其启用和运行状态。正式站点、候选站点的文件与链接链条分别备份；保留文件权限和所有者。证书引用记录包含指令、原始路径、解析目标、链接目标和 SHA-256。快照根目录仅 root 可访问。
3. 写入持久化 `pending` 记录后开始变更。`current` 和环境配置采用原子替换；正式切换同步将 `PLATFORM_PUBLIC_URL` 改为同一主机的 HTTPS 443 地址，保留其他环境项。Nginx 使用正式站点当下的证书引用，候选站点沿用自己的引用，不使用模板硬编码证书覆盖现场证书。
4. 验证新配置的 `nginx -t`，检查四个服务状态、API 数据库健康、适配器密钥访问及流媒体 API，再 reload Nginx 并检查 HTTPS 入口。健康检查要求连续两次服务运行实例不变，失败重试约 60 秒；TLS 使用系统信任及站点证书，仍校验证书链和主机名，禁止关闭验证。
5. 成功后记录 `head` 为最新可回滚操作并清除 `pending`。任何变更阶段失败，均恢复本次操作前的快照、原服务状态并重新校验、reload Nginx，再验证原入口。恢复未完成时返回非零退出码，保留 `pending` 和快照编号用于重试。

8443 候选站点在切换后保留，不自动删除，也不扩大防火墙范围。它与 443 共用 `current`、服务、数据库和会话，并不是独立备份实例；正式切换后从 8443 登录所生成的媒体和下载 URL 也会使用 443。单独 `switch` 保留候选配置原文，安装时按发布模板更新候选配置。TS 的 `protocol.enable_ts=1` 和 Nginx 的 `.live.(flv|ts)` 路由保持启用。

证书指令当前支持站点中直接声明的一组 `ssl_certificate`、`ssl_certificate_key`，以及可选的 `ssl_trusted_certificate`。包含动态变量、多组证书或通过 include 隐藏证书指令的配置会在变更前拒绝处理。脚本只恢复证书引用，不撤销证书续期，也不改写证书和私钥本身。

## 回滚步骤

```powershell
python tools/v2-remote-checks.py rollback
python tools/v2-remote-checks.py rollback --snapshot <最近一次操作的快照编号>
```

第一条恢复待完成操作的 `pending` 快照；没有待完成操作时恢复 `head`。第二条用于核对明确的目标，只接受最近一次操作，不能跳过中间部署直接恢复很早的配置。若服务器已经具备新版安装器，也可执行 `sudo python3 <新版安装器路径> rollback [--snapshot <快照编号>]`。

执行显式回滚前会再保存一份 `rollback-safety` 现场快照，随后按目标快照恢复配置、文件权限、符号链接及服务启用状态。原来未运行的第二版服务会停止；原来运行的服务会重新启动。即使某个服务恢复失败，也会继续尝试恢复其他文件及 Nginx 入口，最终以非零退出码报告恢复未完成。恢复成功后 `head` 回到父操作，下一次执行 `rollback` 将再退一步；不要把重复执行当作同一次操作的无条件重试。

单独切换后的回滚会恢复原正式入口，并保留切换前的 8443 候选和原候选公开 URL；一次安装后的回滚会恢复上一个候选版本及对应配置。首次安装前不存在的候选配置和单元会删除。安装时的数据库初始化及首次生成的生产密钥成对保留，便于失败后重试。操作被强制中断或机器重启后，新的安装和切换会被 `pending` 阻止，应先执行 `rollback`；恢复失败后可排除故障并重试同一快照。

禁止直接拿 `/home/liteware/.config/video-platform/nginx-v1.conf` 覆盖现场；它可能已过时，安装器不再读取该文件。所有回滚均以对应操作前快照为依据，恢复前应核对编号和当前入口状态。快照和历史发布目录不自动清理，应在回滚窗口结束后再安排保留策略。

应用回滚不回退数据库迁移、不删除导出或密钥目录，也不修改录像机录像和摄像头配置。数据库迁移必须保持对上一版本的兼容；不兼容迁移需要单独安排数据库备份和恢复窗口。Nginx 全局配置、独立证书续期、数据库、发布二进制及防火墙不在文件回滚范围内，发布目录应保持不可变。原版服务必须持续可用，才能保证恢复原 443 入口后健康检查通过。

## 安全与更新

内部 API 只允许回环地址和密钥访问，公网只开放 Nginx HTTPS。证书必须由客户端正常校验，不能通过关闭 TLS 验证排障。MSI 和 ZIP 通过版本接口发布，客户端更新器校验下载长度和 SHA-256，失败时保留旧版本并重新启动旧程序。当前安装包没有代码签名证书，发布清单明确标记未签名。
