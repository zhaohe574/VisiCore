## 操作命令

在工作区执行：

```powershell
python tools/v2-soak.py start
python tools/v2-soak.py status
python tools/v2-soak.py stop
```

`start` 默认选择平台返回的前两个在线通道，并在两路首次同时收到有效 MPEG-TS 数据后开始计算 24 小时。`status` 读取服务状态和持久化报告。`stop` 异步提交停止请求，随后应继续执行 `status`，直到看到最终状态和 `cleanupComplete`。

指定两个平台通道 ID：

```powershell
python tools/v2-soak.py start --channels 101 108 --hours 24
```

`101` 和 `108` 是示例平台通道 ID，需要替换为实际值，并非录像机内部通道号。报告同时记录 `channelId`、`deviceId` 和 `deviceChannel`，用于核对实际观测对象；不记录设备名称、密码或媒体地址。

指定入口、证书或 SSH 目标：

```powershell
python tools/v2-soak.py start --channels 101 108 --public-url https://10.37.200.74:8443 --ca-file /etc/nginx/ssl/video-platform.crt
python tools/v2-soak.py start --local-ca-file artifacts/video-platform.crt
python tools/v2-soak.py status --host 10.37.200.74 --ssh-user liteware
```

`--public-url` 会核对会话返回的 HTTPS-TS 地址，不能用它将仍配置为 443 的接口地址悄悄改写到 8443。默认不传此参数，直接使用现场环境配置。`--local-ca-file` 仅适用于本地 `start`，路径位于本机；上传后由 `sudo` 复制到运行目录，优先于服务器的 `--ca-file`，临时上传文件在控制命令结束后删除。`--hours` 支持大于 0 且不超过 168 小时的值；不足 24 小时的运行最多标记为短时运行完成，不能获得 24 小时通过结论。

同一服务器同时只允许一个值守任务。再次 `start` 会创建新的运行编号和独立报告目录，不覆盖历史运行；已有任务仍运行或停止中时拒绝重复启动。`_run` 和 `_control` 是工具内部入口，日常操作仅使用 `start`、`status`、`stop`。

## 验证内容

启动前读取适配器健康信息，要求 `detail.simulated` 明确为 `false`，并检查选中通道所属设备在线且不是回环地址。运行期间继续检查模拟标志，若变为模拟或无法确认该标志，停止本轮观测并记为失败。暂时的适配器访问错误会记入采样失败，不能成为无故障通过。

两路会话均通过平台 `/api/v2/live-sessions` 创建，指定 `streamType=1` 和 `profile=native`，并核对实际响应仍为主码流且 `transcoded=false`。工具直接访问返回的 `httpTsUrl`，完整经过 HTTPS、Nginx、授权和 MPEG-TS 媒体链路，不改写成回环媒体地址、不使用模拟流或转码替代流。拒绝 HTTP 降级、跨入口地址和重定向。

每路独立线程持续消费 MPEG-TS 数据，校验 188 字节传输包的同步字节。连接读取超时为 10 秒，每 60 秒通过平台 API 续期，登录每小时刷新以覆盖 8 小时认证有效期。网络断开、超时或包同步错误会记录失败，再以 5～30 秒退避尝试清理旧会话并重建。认证或授权 401／403 则终止本轮，禁止自动重新登录，保留失败和未完成清理状态。首次两路同时有效收流等待窗口为 5 分钟，选取通道也有独立的 5 分钟上限。

创建会话请求超时可能已在服务端生效；无法取得会话编号时，工具会先注销该路专用登录，清理其关联媒体，然后才允许重建。每路及采样器使用独立登录，避免一个线程的登录恢复干扰另一条有效连接。

传输包同步检查证明媒体字节持续到达，不等同于视频解码、黑屏、冻结、时间戳连续性或人工画面验收；这些内容仍需独立验证。

## 计数口径

| 字段 | 含义 |
| --- | --- |
| `failureCount` | 全部失败事件次数，包括拉流、续期、采样、服务重启及清理失败；恢复成功不清零。 |
| `failuresByCategory` | 按工具固定错误类别累计，只记录类别和次数，不保存异常正文。 |
| `streams[].failures` | 该路消费或重建尝试失败的次数；连续失败重试分别计数。 |
| `streams[].disconnects` | 已经收到有效 TS 的连接因错误被迫终止的次数；包含续期失败触发的主动重建，不包含正常到期或人工停止。 |
| `streams[].outages` | 故障区间次数；首次建立失败也算故障区间，连续重试失败不会重复开启区间。 |
| `streams[].recoveries` | 故障区间后重新收到有效 TS 的次数；初次直接成功不算恢复。 |
| `streams[].connectionsEstablished` | 实际收到有效 TS 的连接总数。 |
| `streams[].reconnections` | 第一条有效连接之后，再次收到有效 TS 的连接次数。 |
| `streams[].outageSeconds` | 已结束故障区间的累计秒数，结束清理时补计未结束区间；断流开始按最近一次有效数据时间估算。 |
| `streams[].renewals`、`renewFailures` | 成功续期次数及失败续期次数，续期失败同时记入该路失败。 |
| `observedSeconds` | 两路首次同时有效收流后的墙钟观测时长，发生故障后不重置。 |

`attempts` 包括进入新一轮创建和拉流的尝试，`bytes` 与 `tsPackets` 分别为已处理字节和通过同步检查的 TS 包数。重连成功只能增加恢复记录，不能被包装成“连续无故障”。

## 资源采样

每分钟采集并写入 JSONL：

- API、Worker、Adapter、ZLM 的主进程 PID、RSS（常驻内存）、CPU、cgroup 内存和 CPU，以及 systemd 自动重启计数和观测到的重启次数。
- 平台实时会话数、回放会话数、在线登录数、在线设备数和通道数；适配器设备、直播和回放条目数；ZLM 当前连接总数。
- 根文件系统、第二版数据目录和报告目录所在文件系统的总量、已用量和剩余空间。小于 1 GiB 的可用空间记为异常。

CPU 百分比采用相邻样本累计 CPU 时间差除以墙钟时间，单核满载为 100%，多核可超过 100%。cgroup 指标覆盖所属服务的子进程，主进程指标单独保留。首个样本及发生重启后的首个 CPU 差值为 `null`，不伪造为零；cgroup 指标不可获取时记为采样失败。

重启检测结合 systemd `NRestarts` 差值和运行实例、PID、进程启动时刻变化，取较大值避免对同一次重启重复计数。它能累计 systemd 自动重启，但分钟采样之间的多次人工重启可能只能观察到一次，因此 `observedRestarts` 是观测下限。采样期间任何可见重启都会使无故障验收失败。

会话数和连接数是平台或服务全局统计，包含其他用户及观测请求；它们不应被解释为值守独占的两个会话。单次资源采样耗时超过 60 秒会记为采样超时异常；持久化线程独立运行，不因资源采样阻塞而停止分钟进度落盘。

## 报告与判定

报告目录为 `/var/lib/video-platform-v2-soak/runs/<运行编号>/`，主要文件：

- `runner.py`：本次任务使用的脚本副本，不含运行凭据。
- `public-ca.pem`：由控制进程复制并交给后台账户读取的公开证书，权限为 `0600`，不包含私钥。
- `events.jsonl`：仅追加的事件、计数、资源样本与分钟进度，每次写入均 flush 和 fsync（同步到磁盘）。
- `progress.json`：最新进度，先写临时文件并 fsync，再原子替换，同时同步目录。独立线程每 60 秒更新，启动、停止和结束时也更新。

密码、登录令牌、内部密钥、媒体 URL、API 原始响应及异常正文都不进入工具报告。后台标准输出和标准错误关闭，禁止生成进程 core dump（内存转储）；这不改变平台或 Nginx 自身的日志设置。报告目录归 `liteware` 所有，报告文件仅该账户及 root 可读。

只有两路达到目标时长、观测至少 24 小时、没有任何失败、已确认真实设备并完成清理，才会生成 `status=passed` 和 `passed=true`。出现恢复或重启后，即使坚持运行满 24 小时，也只能是 `completed_with_failures`。不足 24 小时且无故障的完成状态为 `short_run_completed`；人工提前停止为 `stopped`；启动、后台线程或真实性验证失败为 `failed`。

`status` 会结合 systemd 和进度时间检查结果：进度仍显示运行但服务已经停止时，返回 `effectiveStatus=interrupted`；运行中的进度超过 180 秒未更新时为 `stale`。以上都不能认定通过。磁盘写入失败会停止观测并禁止通过；若连失败状态都无法落盘，以服务状态和陈旧进度判定未完成。

## 停止与清理

正常完成、人工停止和可捕获异常均进入 `finally` 清理：结束媒体消费、删除本次媒体会话并注销各专用登录，失败最多重试三次且逐次计入错误。systemd 给予 180 秒停止窗口，工具内部最多等待后台线程清理 150 秒。

停止请求提交成功不代表清理完成，需检查最终 `cleanupComplete=true`。API 持续不可达、强制终止或机器掉电可能使清理不完整；不要把这类运行判为通过。媒体会话停止续期后约 3 分钟过期，并由平台后台维护清理，仍需主代理核对现场会话和连接是否回落；未注销的登录会话按平台有效期失效。

历史运行目录不自动删除。重新启动值守会生成新的运行编号，旧 JSONL 和报告保留，不能将两次运行的时长拼接为一次连续 24 小时结果。
