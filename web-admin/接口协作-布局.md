# 给 Pauli 的空窗口布局契约说明

根据主代理确认，必须保存真实窗口分配，扩展现有 `channelIds` 字段，不新增另一套布局字段。

## 请求与响应

`LayoutRequest.ChannelIds` 与 `AdministrationLayoutDto.ChannelIds` 改为 `long?[]`，JSON 类型为 `(number | null)[]`。Web 保存固定布局时写满 `layout` 个元素，数组下标从零开始对应窗口下标；例如四分屏 `[101, null, 203, null]`，第二、第四窗口为空。旧的纯数字数组仍按原顺序读取，不足窗口数补空。

保存、读取、授权过滤均保持元素位置与重复通道，不进行 `Distinct`、删除空项或压缩数组。授权校验只检查非空通道；读取共享布局时把当前用户无权访问的通道替换为 `null`，不能删除并使后续通道移动。

布局长度不超过 `layout`，可保存全空布局。轮巡仍是有序通道队列，可兼容空项，但运行时跳过空项，并至少包含一个有效通道。`favorites` 和批量分配等其他 `channelIds` 继续保持非空数字数组。

## 服务端同步项

- 更新 Contracts 类型及数据库 `bigint[]` 读写，允许数组内空值。
- 更新管理服务保存校验与授权查询，保留数组下标和重复通道。
- 更新 SQL 快照读取与 Npgsql 数组映射，避免空项被过滤或转为零。
- 重新生成 OpenAPI 及 `artifacts/v2/generated/web` 客户端；Web 将接入该真实生成产物。
- 增加 `[101, null, 203, null]` 往返测试，以及授权撤销后 `[null, null, 203, null]` 的位置保留测试。

此说明由 Web 代理维护，仅修改 Web 目录。共享主契约文档、服务端及生成工具由主代理和 Pauli 更新。
